# 구석기 역사 체험 웹게임
## Stage 01~05 설계 재검증 v3 / Design Reboot R2

> 목적: 신체화된 1인칭, 관계 기억, 체감형 위협·딜레마, 재수렴형 비획일적 결과를 Stage 01부터 반영한 뒤 Stage 01~05가 서로 충돌하지 않는지 재검증한다.

---

# 1. 재검증 결론

## **기존의 교육 목표와 세 역할 동등성은 유지한다. 그러나 이전 설계의 ‘몰입’은 아직 화면 밖 관찰자의 감각을 충분히 벗어나지 못했다. 이번 리비전은 플레이어의 몸, 관계, 선택 기억을 프로젝트 구조의 필수 요소로 승격한다.**

핵심 추가:

- Embodied First-Person
- 역할마다 다른 Player Body Identity
- 반복 등장 인물
- 관계 기억
- 위협의 징후 선행
- 가치 충돌형 딜레마
- Persistent Consequence
- Reconverging Narrative
- Perspective Recontextualization

---

# 2. Stage 01 검증

## 유지

- 설명보다 경험
- 세 역할 동등성
- 이동은 경험의 결론
- 실패는 정상적인 불확실성
- 자연 속 인간의 취약함

## 강화

기존 `역할 빙의`를 다음 수준으로 구체화했다.

### 이전

> 내가 그 사람이라고 느낀다.

### 현재

> 내 손과 몸이 시야 안에 있고, 특정 사람이 나를 바라보고 말하며, 내가 한 판단을 그 사람이 기억하고, 다른 역할에서 그 사건의 반대편을 다시 경험한다.

판정: **PASS / Project Core v5로 교체**

---

# 3. Stage 01A — Embodied First-Person 검증

필수 이유:

- 단순 1인칭 배경만으로는 `내가 그곳에 있다`는 감각이 약함
- 몸이 보일 때 행동·상태·거리·관계가 화면 안에서 자연스럽게 연결됨

Guardrail:

- FPS화 금지
- 과도한 카메라 흔들림 금지
- 몸을 HUD처럼 붙이는 방식 금지
- 역할 내 신체 연속성 필수

판정: **PASS**

---

# 4. Stage 01B — 관계·선택·결과 검증

필수 이유:

- 위협을 텍스트로 설명하면 체감이 약함
- NPC가 튜토리얼 기능만 하면 공동체성이 약함
- 성공/실패 두 갈래만 있으면 삶의 복합성이 사라짐

해결 구조:

- 관계 = 함께 겪은 사건의 기억
- 위협 = 징후 → 사람 반응 → 관찰 → 판단
- 고민 = 상충 가치
- 결과 = 다축 질적 상태
- 큰 플롯 = 재수렴 가능
- 의미 = 선택 기억에 따라 달라짐

판정: **PASS**

---

# 5. Stage 02 검증

새 구조는 `Common Morning 한 번`의 개념을 세계 사건과 관점 경험으로 분리했다.

- Shared Morning Event: 세계 안에서 한 번 발생
- Perspective Morning Echo: 각 역할 몸에서 같은 아침을 짧게 다시 경험

이 방식은 같은 하루 동시성을 강화하면서 반복 설명을 피한다.

Perspective Bridge도 역할 메뉴가 아니라 **몸과 사람의 시점 이동**으로 재정의했다.

판정: **PASS**

---

# 6. Stage 03 Hunt STORY 검증

Hunt v4는 다음을 충족한다.

- 첫 장면부터 몸과 사람
- 반복 관계 인물 R/H1/H2
- 동행자가 정답 NPC가 아님
- 추적 고민 전에 욕구·시간·피로·관계 정보가 존재
- 위험이 UI보다 먼저 느껴짐
- food outcome 외 시간·거리·위험·관계 축 존재
- 귀환 반응이 상태에 따라 변주 가능
- Camp 관점에서 Hunt의 반대편을 재해석 가능

판정: **PASS**

---

# 7. Stage 04 Hunt PLAYFLOW 검증

PLAYFLOW v4는 장면마다 다음 계약을 요구한다.

- POV
- 보이는 몸
- 사람 위치
- 행동
- 즉시 반응
- 관계 기억
- 시간/거리/위험 변화
- 뒤에서의 회수

이 계약은 기존 설명 카드형 구현의 재발을 막는다.

판정: **PASS**

# 8. Stage 05 Role Map 검증

역할별 고유성:

## Hunt

멀리 보기 / 걷기 / 흔적 앞에 몸 낮추기 / 위험 / 귀환

## Gather

가까이 보기 / 손으로 살피기 / 담기 / 공간 비교 / 탐색 범위 확대

## Camp

불 가까이의 몸 / 손질 / 같은 공간 반복 보기 / 부재 / 멀리 바라보기 / 재회

따라서 `1인칭`을 하나의 공통 템플릿으로 만들지 않는다.

판정: **PASS**

# 9. 발견된 설계 리스크

## 리스크 A — 이미지 생성 일관성

1인칭 몸이 장면마다 달라질 수 있다.

대응:

- 역할별 Player Body Continuity Sheet
- POV 높이/손/도구/광원 기준
- 최종 이미지 전 Visual Continuity QA

## 리스크 B — 분기 폭발

관계·결과를 강화하면 장면 수가 급증할 수 있다.

대응:

- Bounded Agency
- 명시적 질적 상태
- 중요한 장면만 변주
- 큰 플롯 재수렴

## 리스크 C — 관계의 역사적 과단정

구체 친족/권력 구조를 사실처럼 보일 위험.

대응:

- `[재구성]` 명시
- 초기에는 관계 기능 중심
- 역사 검토 후 세부 설정 확정

## 리스크 D — 1인칭 조작 과잉

3D 자유 이동이 학습보다 커질 위험.

대응:

- Cinematic First-Person Interactive Scene
- 제한된 시야 조작
- 의미 있는 상호작용만 사용

## 리스크 E — 선택이 숨겨진 정답이 되는 문제

대응:

- 각 주요 딜레마에 장단점 명시
- 특정 루트 독점 보상 금지
- 관계/시간/공간 결과를 질적으로 표현

# 10. Stage 06에 요구하는 기술 조건

기술 설계는 반드시 다음을 지원해야 한다.

1. Embodied POV scene composition
2. 역할별 Player Body Identity
3. 반복 등장 인물의 최소 continuity
4. 역할 내부 relationship memory
5. 필요한 최소 cross-role shared memory
6. 다축 qualitative consequence
7. Narrative variant selection
8. Perspective Bridge의 시점 전환
9. Player-facing / Debug 분리
10. 분기 폭발을 막는 재수렴 구조

이 요구를 지원하지 못하면 Stage 06은 재작성한다.

---

# 11. 최종 판정

## Stage 01~05 Design Reboot R2: **PASS**

단, 이 PASS는 **문서 설계 정합성**에 대한 판정이다.

아직 증명하지 않은 것:

- 실제 화면에서 몸이 자연스럽게 보이는가
- 주변 인물이 실제 사람처럼 느껴지는가
- 위협이 설명 없이 위협으로 다가오는가
- 딜레마가 실제 고민이 되는가
- 비획일적 결과가 선택의 의미를 살리는가

이는 새 기술 설계와 차기 프로토타입에서 검증해야 한다.
