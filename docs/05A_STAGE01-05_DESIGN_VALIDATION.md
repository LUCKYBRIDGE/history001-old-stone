# 구석기 역사 체험 웹게임
## Stage 01~05 설계 재검증 v2 — Stage 09 몰입 피드백 반영

> 목적: Stage 01~05의 기존 교육·역할 균형 결론이 Stage 09-A 실제 플레이에서 발견된 `HUX-001 — 시작 직후 역할 몰입 부족` 이후에도 유효한지 재검증한다.

---

# 1. 재검증 결론

## **기존 교육 방향과 역할 경계는 유효하다. 그러나 ‘학생이 실제로 그 생활 속에 들어간다’는 최상위 목표를 구현 수준까지 연결하는 몰입 설계가 부족했다.**

즉, 기존 설계를 폐기하지 않는다.

다만 다음이 새 필수 조건이 되었다.

- 역할 빙의(Role Embodiment)
- 시작 20~30초의 세계 진입
- 몸/감각
- 관계 인물
- 설명보다 행동
- 선택 직후 세계 반응
- 시간·공간 연속성
- 모티프/감정 회수
- Player-facing UI와 개발 메타 UI 분리

이 조건은 `docs/07_IMMERSION_NARRATIVE_BIBLE.md`에 canonical 기준으로 정리했다.

---

# 2. Stage 01 — Project Core 재검증

기존 핵심:

- 설명이 아니라 생활 속 경험
- 세 역할의 동등성
- 이동은 경험의 결론
- 실패는 정상적인 불확실성

판정: **유지 + 강화**

문제:

`생활 속에 들어간다`는 문장이 선언 수준에 있었고 실제 장면 작성 기준이 약했다.

보강:

- v4에서 역할 빙의를 학습 메커니즘으로 명시
- `상황 → 행동 → 결과/감각 → 연결 → 개념화` 순서 고정
- 시작 30초 Gate 추가

---

# 3. Stage 02 — Experience Structure 재검증

기존 핵심:

- 하나의 공동체가 보내는 하루
- 공통 아침
- 세 역할
- 공통 저녁
- 며칠 변화
- 이동

판정: **구조 유지 + 진입/전환 방식 수정**

문제:

공통 아침과 RoleEntry가 기능적으로는 맞지만 `안내 화면`처럼 구현될 여지가 컸다.

보강:

- 공통 아침을 Cold Open으로 재정의
- 역할 진입을 메뉴 선택보다 정체성 전환으로 정의
- Perspective Bridge에 같은 불/해/사람의 연속성 원칙 추가
- 공통 저녁을 감정적 재회로 강화

---

# 4. Stage 03 — Hunt STORY 재검증

기존 강점:

- `해가 지기 전에 돌아와` 모티프
- 탐색/불확실성/위험/귀환
- 성공/빈손 모두 정상

판정: **핵심 주제 유지 + 줄거리 대폭 강화**

문제:

사건의 의미는 좋았으나 플레이어의 몸, 관계, 장소 연속성이 충분히 구체화되지 않아 `내 이야기`가 되기 어려웠다.

보강:

- 불 옆의 새벽 Cold Open
- `같이 가자` 관계 진입
- 함께 나가는 사람 A/B
- 기다리는 사람
- 멀어지는 거처
- 발견 전 정적
- 위험에서 동행자 반응
- 귀환 랜드마크 회수
- 같은 불의 아침/저녁 의미 변화

---

# 5. Stage 04 — Hunt PLAYFLOW 재검증

기존 강점:

- 사냥 고유 내부 상태 분리
- 탐색, 접근, 추적, 위험, 귀환
- 점수/전투 배제

판정: **기능 문법 유지 + 학생 경험 문법 재설계**

문제:

`장면 제목 + 설명 + 선택/다음` 반복이 웹 프로토타입 감각을 강화할 수 있었다.

보강:

- 상황을 먼저 보여주고 선택은 뒤에 배치
- 선택 직후 환경/사람/시간 반응 필수
- 개발 stage label 학생 화면에서 제거
- 귀환 단서를 앞 장면에 미리 심어 기억 회수로 변경
- 첫 30초 직접 행동 필수

---

# 6. Stage 05 — Role Experience Map 재검증

기존 핵심:

- 역할 간 침범 금지
- 역할 동등성은 분량 동일이 아님
- Gather/Camp를 Hunt 복사본으로 만들지 않음

판정: **유지 + 역할별 몰입 문법 추가**

보강:

## Hunt

멀어짐 / 추적 / 위험 / 귀환 / 불빛.

## Gather

익숙한 가까운 장소 / 반복 관찰 / 공간 기억 / 탐색 범위 확대.

## Camp

같은 장소 / 불 / 시간 변화 / 빈 자리 / 기다림 / 귀환 신호.

역할마다 `몸과 공간을 느끼는 방식`까지 달라져야 한다.

# 7. 새로 발견된 시스템 수준 위험

## 위험 A — 교육적 의미는 맞지만 체험은 설명형

대응:

Immersion Gate를 Functional Gate와 분리한다.

## 위험 B — 최종 아트가 몰입 문제를 해결해줄 것이라는 기대

대응:

CSS/text prototype에서도 기본 역할 빙의를 검증한 뒤 아트로 증폭한다.

## 위험 C — 몰입 강화를 위해 과도한 서사/텍스트 추가

대응:

줄거리는 강화하되 **긴 설명이 아니라 행동·관계·공간 연속성**으로 전달한다.

## 위험 D — 몰입을 위해 범용 Scene/NPC/Dialogue Engine을 과설계

대응:

기술 구조는 기존 Feature 경계를 유지하고 Shared UI는 표현 primitive 수준에 한정한다.

## 위험 E — 사실적인 디테일을 위해 역사적으로 불확실한 요소를 확정

대응:

교과 사실 / 재구성 / 게임 구분을 유지하고 강한 시각 세부는 별도 역사 검토를 거친다.

---

# 8. 새 설계 품질 기준

Stage 01~05에서 파생되는 모든 후속 역할은 다음 질문에 답할 수 있어야 한다.

1. 학생은 첫 30초에 어디에 있다고 느끼는가?
2. 어떤 사람과 관계가 있는가?
3. 몸으로 무엇을 보고/듣고/느끼는가?
4. 왜 지금 행동해야 하는가?
5. 설명 없이 무엇을 먼저 직접 하는가?
6. 선택 뒤 세계가 어떻게 반응하는가?
7. 앞에서 본 것이 뒤에서 어떻게 회수되는가?
8. 이 역할만의 몰입 문법은 무엇인가?
9. 이 역할을 빼면 전체 역사 이해에서 무엇이 사라지는가?
10. 학생이 플레이 경험을 근거로 어떤 역사적 이유를 말할 수 있는가?

---

# 9. 최종 판정

Stage 01~05의 교육·역할 구조는 폐기할 이유가 없다.

오히려 Stage 09-A 피드백은 기존 최상위 문장

> **“구석기 시대를 설명하는 웹이 아니라 생활 속에 들어가 보는 웹”**

을 더 엄격하게 구현해야 한다는 증거다.

따라서 이번 리비전은 방향 전환이면서 동시에 **초기 목표를 실제 플레이 수준까지 밀어붙이는 강화 작업**으로 판정한다.
