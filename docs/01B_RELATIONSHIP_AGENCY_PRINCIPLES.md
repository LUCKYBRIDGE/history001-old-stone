# 1. 핵심 정의

관계는 NPC 호감도 시스템이 아니다.

# **관계 = 함께 겪은 사건을 서로 기억하고, 그 기억 때문에 이후 행동·대사·시선·침묵·기다림의 의미가 달라지는 것**

선택은 정답 버튼이 아니다.

# **선택 = 당시 보이는 조건과 관계 속에서 판단하고, 그 판단의 흔적을 이후 세계·사람·내 감정이 기억하는 것**

결과 구조:

# **Bounded Agency + Persistent Consequence + Emotional Reality + Reconverging Narrative**

큰 역사적 흐름은 다시 만날 수 있지만 학생의 하루가 같은 의미로 지워져서는 안 된다.

---

# 2. 감정은 학습의 방해물이 아니라 역사 체험의 일부다

이 프로젝트는 감정을 중립화하지 않는다.

역사적 생활 조건에서 자연스럽게 생길 수 있는 다음 감정은 적극 활용할 수 있다.

- 두려움
- 긴장
- 죄책감
- 후회
- 걱정
- 안도
- 책임감
- 애착
- 답답함
- 아쉬움
- 의견 충돌
- 성취감
- 무력감의 짧은 순간

중요한 것은 감정의 존재 여부가 아니라 **왜 그 감정이 생겼는가**다.

좋은 예:

> 더 추적하느라 해가 많이 낮아졌다.
>
> 돌아왔을 때 기다리던 사람이 말없이 내 얼굴을 먼저 본다.
>
> 학생이 `조금 더 일찍 돌아올 걸 그랬나`라고 느낄 수 있다.

이 감정은 정답 판정이 아니라 **관계와 결과를 이해한 데서 생기는 역사적 상상력**이다.

---

# 3. 죄책감은 금지하지 않는다 — 조작적 죄책감을 금지한다

학생이 자기 판단 때문에 누군가를 걱정시키거나 부담을 키웠다고 느끼는 것은 현실적인 결과가 될 수 있다.

허용:

- 늦은 귀환 때문에 기다린 사람이 걱정한 사실을 알게 됨
- 빈손으로 돌아와 공동체의 어려움을 체감함
- 무리한 판단 뒤 함께 있던 사람이 더 지친 모습을 봄
- 다른 관점에서 자신의 이전 행동이 타인에게 어떤 의미였는지 깨달음
- 결과를 보고 `다르게 할 수도 있었겠다`고 스스로 생각함

피할 것:

- `너 때문에 모두가 굶었다`처럼 복잡한 상황을 학생 한 명의 잘못으로 단정
- NPC가 모욕·조롱·인신공격
- 죄책감만 강하게 주어 특정 선택을 사실상 정답으로 강요
- 한 선택을 영구적인 `나쁜 사람` 상태로 낙인
- 역사적 불확실성을 도덕 판정으로 치환

# **죄책감은 결과를 이해한 학생에게서 생길 수 있지만, 시스템이 학생을 심리적으로 몰아붙이는 채점 도구가 되어서는 안 된다.**

---

# 4. 주변 인물은 기능 카드가 아니다

각 역할에는 반복해서 만나는 소수의 사람이 필요하다.

인물은 다음으로 기억된다.

- 얼굴/목소리/자세/손짓 같은 일관된 존재
- 나와 함께 한 사건
- 나에게 한 짧은 말
- 내가 그 사람 앞에서 한 판단
- 이후의 반응
- 나와 공유한 두려움·기다림·안도

피할 것:

- `동행자 A: 신중한 성격`
- 관계 설명 카드
- 호감도/친밀도 숫자
- 정답을 대신 말하는 튜토리얼 NPC
- 언제나 현명한 인물과 언제나 무모한 인물의 고정 역할
- Player-facing `도구를 건네는 사람`, `함께 나가는 사람`, `주변을 살피는 사람` 같은 제작 기능 설명

좋은 관계는 **반복되는 상호작용과 기억, 감정의 회수**로 만든다.

---

# 4A. Player는 이 세계를 처음 방문한 사람이 아니다

Player character는 구석기 세계에 처음 도착한 현대 학생이 아니다.

# **Player character는 Day 1 이전부터 이 공동체에서 살아온 한 사람이다.**

학생만 처음 이 몸과 관계를 이어받는다.

따라서 Player-facing scene은 주변 사람과 생활 공간을 관광객에게 설명하듯 소개하지 않는다.

피할 것:

- `저 사람은 너와 함께 사는 사람이다.`
- `이 사람은 사냥에 같이 나가는 사람이다.`
- `여기가 네가 사는 임시 거처다.`처럼 Player character가 이미 알아야 할 것을 장황하게 설명

권장:

- 익숙한 이름이 다른 사람의 말 속에서 자연스럽게 불림
- 특정 사람이 평소 하던 듯한 몸짓을 반복함
- Player character는 사람/장소를 처음 본 사람처럼 놀라지 않음
- 학생은 반복 행동·위치·shared event를 통해 관계를 따라잡음

# **학생에게 설명하기 위해 Player character의 기존 삶을 지워서는 안 된다.**

---

# 4B. Authoring ID와 Player identity를 분리한다

R/H1/H2 같은 내부 ID는 제작·상태·테스트를 위해 유지할 수 있다.

하지만 이것은 사람의 Player-facing 정체성이 아니다.

```text
R/H1/H2 = authoring identity
이름/얼굴/목소리/습관/shared memory = Player가 기억하는 character identity
```

Player에게 다음을 character 소개로 노출하지 않는다.

- R / H1 / H2
- return anchor
- shared-action anchor
- observation anchor
- `도구를 주는 사람`
- `기다리는 사람`
- `주변을 보는 사람`

기능은 내부에서 장면 누락 여부를 검사하는 용도로만 쓴다.

# **관계 기능은 사람이 되기 위한 체크리스트이지, 사람을 대신하는 이름표가 아니다.**

---

# 4C. 가상 이름과 언어 Convention

핵심 반복 인물에게 짧은 가상 이름을 부여할 수 있으며, 기본적으로 권장한다.

이름 조건:

- 초등학생이 한두 번 듣고 구분할 수 있음
- 핵심 인물끼리 음운적으로 충분히 다름
- 특정 현대 민족/국가의 실제 이름처럼 강하게 고정되지 않음
- `우가`, `우구` 같은 원시인 희화화 금지
- 실제 구석기 이름이라고 주장하지 않음

구체 이름은 **Historical Reconstruction**이다.

이름은 character card에서 외우게 하지 않는다.

권장:

```text
다른 사람이 이름을 부름
→ 해당 인물이 고개를 돌림
→ 이후 같은 이름과 몸/목소리/행동이 반복됨
```

Player 화면의 한국어 대사 역시 실제 선사 언어를 재현한다고 주장하지 않는다.

# **당시 구체 언어 형태는 알 수 없으므로, 게임의 한국어 대사는 학생이 의미를 이해할 수 있도록 번역된 표현이다.**

따라서 다음은 피한다.

- `우가! 우우! (같이 가자)`처럼 괴성을 원시 언어로 가정
- 구석기 사람이 언어를 제대로 사용하지 못했다는 인상을 주는 표현
- 서로 이미 아는 내용을 현대 교과서처럼 길게 설명하는 exposition dialogue

대사는 상황 안에서 짧게 사용한다.

예:

- `가자.`
- `잠깐.`
- `저기.`
- `늦어.`
- `돌아가자.`
- `왔네.`

---

# 4D. Character는 습관 + 공유된 과거 + 오늘의 사건 + Callback으로 만든다

핵심 반복 인물은 최소 다음을 가진다.

```text
1. Player-facing name
2. embodied habit / 반복 습관
3. Player와 공유된 과거의 작은 암시
4. 오늘의 shared event
5. 이후 callback
```

성격을 label로 알려주지 않는다.

피할 것:

- `다정한 사람`
- `용감한 사람`
- `관찰력이 뛰어난 사람`

대신:

- 걱정할수록 말이 짧아짐
- 먼저 걸어도 Player가 늦으면 기다림
- 대화 중에도 시선이 다른 곳으로 빠짐
- 위험 때 말없이 사람 사이 거리를 줄임

같은 반복 행동으로 학생이 스스로 인상을 만든다.

공유된 과거 역시 긴 회상 설명보다 작은 흔적으로 암시한다.

예:

> `이번에는 놓치지 마.`

이 대사가 실제 과거 사건을 암시한다면 그 과거 역시 재구성으로 관리한다.

---

# 4E. NPC Autonomy — Player가 없어도 사람들은 살아 있다

NPC는 Player에게 대사·정보·버튼을 제공하기 위해서만 존재하지 않는다.

필수 원칙:

- Player가 눈을 뜨기 전에도 생활 소리·대화·행동이 이어질 수 있음
- Player가 등장했다고 모든 사람이 동시에 바라보지 않음
- 핵심 인물끼리 짧은 대화·의견 차이·도움·무시·기다림이 가능
- 모든 대사가 Player에게 정보를 전달할 필요가 없음
- background actor는 이름 없이도 불 관리·재료 정리·거처 손질·휴식 같은 생활 행동을 할 수 있음

# **Player는 세계의 중심이 아니라 이미 움직이고 있던 공동체에 속한 한 사람이어야 한다.**

핵심 인물만 존재하는 RPG party처럼 보이지 않도록 한다.

공동체의 정확한 인원수나 구체 사회 구조를 역사적 보편 사실로 가르치지는 않는다.

# 5. 관계의 최소 기능

모든 역할에서 다음 기능을 **제작자 관점에서** 검토한다.

## 함께 행동하는 사람

내 판단을 보고 반응하며 노동·위험·이동을 함께 겪는다.

## 기다리거나 의존하는 사람

내가 보지 않는 곳에서도 존재하며 귀환과 결과의 의미를 만든다.

## 의견이 다른 사람

같은 상황을 다르게 판단할 수 있다. 한쪽이 항상 정답 NPC가 되지 않는다.

## 다른 관점에서 다시 만나는 사람

한 역할에서 보았던 사람이 다른 역할에서는 `나`가 되거나 반대편 위치에서 같은 사건을 경험한다.

모든 역할에 정확히 네 명을 배치하라는 뜻은 아니다. **관계 기능이 살아 있어야 한다.**

단, 이 네 기능을 Player-facing 인물 소개로 그대로 번역하지 않는다.

# 6. 관계는 숫자 대신 Memory Signal

예시:

- `stayed-together-under-danger`
- `followed-companion-warning`
- `pressed-on-despite-fatigue`
- `shared-carry-burden`
- `returned-late`
- `returned-empty-handed`
- `noticed-waiting-person`
- `companion-worried-after-choice`
- `regretted-pushing-farther`

학생에게 내부 ID를 보여주지 않는다.

이 기억은 다음을 바꿀 수 있다.

- 시선
- 짧은 대사
- 침묵
- 누가 먼저 행동하는가
- 누가 부담을 나누는가
- 귀환의 정서
- Perspective Bridge
- Common Evening
- 다음 관점에서 학생이 느끼는 의미

Memory Signal은 점수가 아니지만 **좋고 나쁜 감정이 전혀 없는 무색무취한 기록도 아니다.**

Memory는 `성격 수치`보다 **누가 무엇을 함께 겪었는가**를 우선 기록한다.

예:

```text
morning-fire-together
r-gave-player-handaxe
return-line-heard
shared-track-observation
waited-for-player
pushed-farther-together
returned-late
```

구체 schema와 persistence는 `docs/06_TECH_BLUEPRINT.md`만 소유한다.

# 7. 위협과 공포는 상황에 따라 강해질 수 있다

목표는 공포게임을 피하는 것이 아니라 **공포가 역사적 상황을 강화하는지**를 판단하는 것이다.

기본 문법:

# **징후 → 다른 사람 반응 → 내 몸의 변화 → 내 관찰 → 위협의 접근 → 판단 → 결과/회복**

허용 가능한 공포 요소:

- 어둠 속에서 정체를 바로 알 수 없는 소리
- 가까워지는 움직임
- 순간적인 놀람
- 갑작스러운 함께 있던 사람의 정지
- 시야 밖 존재에 대한 불확실성
- 짧은 추격/회피 느낌
- 실제로 위험할 수 있다는 압박
- 한 번의 강한 사건 뒤 남는 긴장

특히 Hunt에서는 `사냥하는 인간도 자연 속에서는 먹이사슬과 위험에서 자유롭지 않다`는 감각이 중요하다.

피할 것:

- 고어를 몰입의 핵심으로 삼기
- 잔혹함 자체를 볼거리로 소비
- 의미 없는 반복 jump scare
- 위협을 적 HP/처치 루프로 환원
- 공포만 남고 역사적 상황이 사라지는 구성

# **공포게임 같은 순간이 있어도 된다. 게임 전체의 목적이 공포 소비로 바뀌지만 않으면 된다.**

# 8. 고민은 가치 충돌이어야 한다

좋은 딜레마에서는 선택 전에 다음이 보인다.

- 원하는 것
- 가능성
- 비용/부담
- 시간/공간 조건
- 다른 사람의 상태
- 관계상 의미

Hunt 예:

- 흔적은 선명해짐
- 먹을 것은 필요함
- 해는 낮아짐
- 거처는 멀어짐
- 함께 온 사람은 지침
- 누군가는 기다림

그 뒤 여러 합리적 선택이 존재한다.

선택 후 학생은 안도·아쉬움·후회·죄책감·성취감 중 무엇이든 느낄 수 있다.

---

# 9. Choice Fairness는 감정적 결과까지 포함한다

중요한 선택은 다음을 통과한다.

- 선택 전에 판단에 필요한 핵심 조건이 관찰 가능했는가?
- 적어도 두 선택이 당시 상황에서 이해 가능한 이유를 갖는가?
- 결과가 완전히 예측 가능할 필요는 없지만 세계의 조건과 연결되는가?
- 나중에 결과를 보고 앞선 판단과 연결할 수 있는가?
- 특정 선택만 핵심 역사 콘텐츠를 독점하지 않는가?
- 관계 반응이 단순 `보상/벌`보다 상황의 결과처럼 느껴지는가?

모든 선택이 동일하게 편안하거나 동일하게 긍정적일 필요는 없다.

# **공정함은 모든 선택을 똑같이 좋은 선택으로 만드는 것이 아니라, 결과가 납득 가능하도록 만드는 것이다.**

---

# 10. 선택 결과의 다섯 층

## 즉시 결과

- 사람 반응
- 위치 변화
- 정보
- 시간 경과

## 장면 후 결과

- 위험 맥락
- 피로
- 거리
- 운반 부담

## 관계 결과

- 이후 대사
- 침묵
- 도움/망설임
- 귀환 반응

## 정서 결과

- 안도
- 후회
- 죄책감
- 걱정
- 자신감
- 긴장 지속

## 통합 결과

- Perspective Bridge
- Common Evening
- 며칠 변화
- 다른 역할에서의 재해석

모든 선택이 다섯 층을 다 바꿀 필요는 없다.

---

# 11. Learning Invariants를 분기로 잃지 않는다

Narrative Variant가 달라도 핵심 역사 학습은 보존한다.

예:

- Hunt의 어느 경로에서도 사냥의 불확실성·시간/거리 부담·관계·귀환 의미가 드러나야 한다.
- 학생이 특정 선택을 하지 않았다는 이유로 불 사용, 공동체 상호의존, 이동 생활 같은 핵심 개념 전체를 놓치지 않게 한다.

다만 모든 학생이 **완전히 동일한 장면**을 볼 필요는 없다.

# **핵심 역사적 조건은 공유하고, 개인적 경험과 감정은 달라질 수 있다.**

---

# 12. 획일적 결론을 피하는 방법

`성공/실패` 두 엔딩만 두지 않는다.

Hunt 예:

- 먹을 것 확보 + 비교적 일찍 귀환 + 안도
- 먹을 것 확보 + 늦은 귀환 + 기다리던 사람의 걱정
- 먹을 것 확보 + 높은 위험 노출 + 함께 있던 사람과 강한 기억
- 빈손 + 일찍 귀환 + 아쉬움
- 빈손 + 먼 추적 + 후회 가능성
- 빈손 + 위험에서 함께 벗어남 + 관계 강화

이 상태들은 같은 거처로 돌아올 수 있다.

하지만

- 내 몸
- 들고 있는 것
- 사람 위치
- 대사/침묵
- 내가 느끼는 정서적 여운
- 저녁 분위기
- 다음 관점

이 달라질 수 있다.

# **같은 장소에 도착해도 같은 의미로 끝나지 않는다.**

---

# 13. Perspective Recontextualization과 Limited Knowledge

강한 결과는 다른 관점에서 이전 선택의 반대편을 볼 때 생긴다.

예:

Hunt에서 늦게 귀환.

Camp에서는 같은 시간에

- 해가 낮아짐
- 비어 있는 자리
- 밖을 살피는 사람
- 생활을 계속 이어가야 함

을 경험한다.

이때 학생이 `내가 늦게까지 간 동안 저 사람들은 이렇게 기다렸구나`라고 느끼며 죄책감이나 이해가 생길 수 있다.

그 감정 자체를 막지 않는다.

목표:

# **한 행동이 다른 사람에게 어떤 의미가 될 수 있는지 몸으로 상상하게 하는 것**

이다.

동시에 다음 원칙을 지킨다.

# **World Truth ≠ Character Knowledge**

- 어떤 사건이 세계에서 일어났다고 모든 인물이 자동으로 알지 않는다.
- 직접 본 사람, 함께 겪은 사람, 나중에 전달받은 사람을 구분한다.
- 다른 관점은 이전 관점의 hidden debug state를 자동으로 공유하지 않는다.
- 지식 전달 자체가 대화·물건·흔적·귀환 같은 사건이 될 수 있다.

따라서 Perspective Shift는 정보량도 달라야 한다.

# **같은 Day 1을 공유한다고 해서 같은 지식을 공유하는 것은 아니다.**

---

# 14. Common Evening 통합

질적 신호를 아이콘/점수가 아니라 장면으로 번역한다.

`returned-empty-handed`

→ 기다리던 사람이 내 손보다 먼저 얼굴을 봄.

`returned-late`

→ 해가 거의 진 상태, 불 옆의 침묵, 걱정 섞인 짧은 반응.

`shared-carry-burden`

→ 함께 돌아온 사람과 같이 내려놓는 행동.

`danger-close-call`

→ 돌아온 뒤 잠시 말이 줄고 서로 얼굴을 확인함.

학생이 장면을 보고 감정을 해석하게 한다.

---

# 15. 관계의 역사적 안전성

구체 친족/권력 구조를 근거 없이 사실처럼 단정하지 않는다.

- `엄마`, `아빠`, `족장` 같은 관계는 근거와 교육적 필요 검토 후 사용
- 핵심 반복 인물의 구체 이름·개인 관계·과거 사건은 가상 재구성으로 사용 가능
- 이름을 실제 구석기 이름/언어의 증거처럼 제시하지 않음
- R/H1/H2 같은 제작 ID와 기능 관계는 Teacher/Debug/authoring에서 관리
- Player-facing에서는 기능 관계를 사람의 정체성처럼 설명하지 않음
- 한국어 대사는 의미 전달을 위한 번역 convention으로 관리

가상 개인 관계는 내부적으로 `[재구성]`이다.

관계가 재구성이라고 해서 감정을 약하게 만들 필요는 없다. 단, 재구성을 역사적 보편 사실로 포장하지 않는다.

# **역사적 안전성을 이유로 사람을 익명 기능 카드로 만들 필요는 없다.**

---

# 16. 기술적 Guardrail

과설계하지 않는다.

- 범용 NPC AI 금지
- 복잡한 호감도 경제 금지
- 대규모 대화 트리 금지
- 무한 분기 금지
- 절차 생성 서사 금지

초기 구현은 **작은 질적 상태 + 명시적 변주 + 감정적 callback**으로 충분하다.

필요한 최소 기술 개념:

- Character identity
- Event participant / witness
- Shared memory signal
- Perspective-specific known event
- 명시적 knowledge transfer

구체 schema와 persistence 계약은 `docs/06_TECH_BLUEPRINT.md`만 소유한다.

---

# 17. Acceptance Gate

- 기억되는 사람이 있는가?
- 그 사람을 `도구 주는 사람/관찰하는 사람` 같은 기능이 아니라 이름·몸짓·목소리·shared event로 기억하는가?
- Player가 이 공동체를 처음 방문한 사람보다 원래 속해 있던 사람처럼 느껴지는가?
- NPC가 Player가 보고 있지 않아도 자기 생활과 서로의 관계를 가질 것처럼 느껴지는가?
- 이름이 character card 암기보다 장면 속 반복으로 자연스럽게 연결되는가?
- 한국어 대사가 선사 언어를 함부로 재현하거나 원시인 caricature를 만들지 않는가?
- 관계가 내 판단을 실제로 무겁게 만드는가?
- 죄책감·후회·안도 같은 감정이 생기더라도 상황에서 자연스럽게 발생하는가?
- 시스템이 학생을 모욕하거나 도덕 점수로 몰아붙이지 않는가?
- 위협이 실제로 긴장되거나 무서울 수 있는가?
- 공포가 역사적 상황과 자연의 불확실성을 강화하는가?
- 주요 고민이 실제 장단점과 관계 의미를 가지는가?
- 결과가 뒤에서 몸·사람·감정 중 하나 이상으로 회수되는가?
- 같은 큰 결론으로 가도 개인적 의미가 달라지는가?
- 다른 관점에서 이전 행동의 의미를 다시 느낄 수 있는가?
- 다른 관점의 인물이 자신이 알 수 없는 정보를 자동으로 알고 있지 않은가?
- 같은 사람의 아침 행동/말이 나중에 callback으로 다른 의미를 갖는가?

이 Gate를 통과하지 못하면 Relationship/Agency Complete가 아니다.
